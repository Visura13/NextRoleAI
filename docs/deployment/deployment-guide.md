# Deployment guide

## Render Blueprint

1. Merge Part 9 to `main` and sign in to Render with the GitHub account that can access the public repository.
2. Create a Blueprint from `render.yaml`.
3. When prompted, set `Cors__AllowedOrigins__0` to the final React URL and `VITE_API_BASE_URL` to the final API URL, without a trailing slash.
4. Keep notification delivery disabled, or set `Notifications__Enabled=true`, add a Resend API key, and set a verified sender address.
5. Deploy and wait for PostgreSQL, API migration, and static-site build to complete.
6. Verify `https://YOUR-API/health`, `https://YOUR-API/swagger`, and the React URL in an incognito window.

The database has no public IP allow-list. The API receives its internal database URL dynamically and converts it for Npgsql. The JWT signing key is generated by Render. Do not copy database or signing credentials into source, screenshots, or the report.

The free configuration's CV directory is private but ephemeral. Avoid redeploying between final evidence capture and marking, or re-upload the demonstration CV. A persistent disk/object store is the documented production upgrade.

## Flutter APK

Every successful Flutter CI run uploads `NextRoleAI-android-debug` for 30 days. Download it from the workflow run's Artifacts section. To build against the public API locally:

```powershell
cd mobile
flutter build apk --debug --dart-define=NEXTROLEAI_API_BASE_URL=https://YOUR-API
```

The APK appears at `mobile/build/app/outputs/flutter-apk/app-debug.apk`. Debug signing is acceptable for marker installation; it is not a production-store release signature.

## Startup and smoke-check order

1. PostgreSQL is available.
2. API starts and applies migrations.
3. `/health` and `/swagger` respond.
4. React loads with the API URL compiled into the Vite build.
5. Flutter is built with the same API URL.
6. Create separate Job Seeker and Recruiter test accounts; never publish real credentials in the public repository.
